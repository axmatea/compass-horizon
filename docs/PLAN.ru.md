# Longview: разбор плана COMPASS и собственный план

## Что в плане COMPASS сильное (сохранено в Longview)
1. Честность как принцип: синтетика и ускоренное время помечены, BLOCKED вместо скрытых моков, «insufficient evidence» вместо «победителя».
2. Правильные примитивы длинного горизонта: два времени у события, идемпотентность, версии правил, чекпоинты, resume.
3. Точный хук: дешёвый лид не равен хорошему клиенту.
4. У каждого спонсора функция, а не логотип. Один интегратор, feature freeze, тестовая матрица.

## Слабости
1. Объём не по времени: инвайты, тенанты, Better Auth, PWA, голос, 4 экрана, очередь, 3 спонсора и Railway за один день. Судьи не заходят в ваш кабинет, а риск не довезти ядро высокий.
2. Brownfield: перестройка голосового конструктора сайтов, локальная копия отстаёт, модули AI Media не закоммичены, голос этой истории не нужен.
3. Длинный горизонт не виден глазами: поздний ответ приходит по кнопке, агент не держит обещаний во времени, нельзя посмотреть, что агент знал на 3-й день. Со стороны это CRM с вебхуком.
4. Нет драмы: агент ни разу не ошибается и не меняет мнение, запомнить нечего.
5. Mobile-first для B2B-инструмента, который жюри смотрит на проекторе.
6. Спонсоры неглубоко (Liquid только извлечение, Tinybird только счётчики), доступы не подтверждены, а этапы от них зависят.
7. Три исполнителя на одном main, UI строится против API, которого ещё нет: узкое горлышко на merge перед дедлайном.

## Longview: план
**Концепция.** Агент, который ждёт правды. Инсайт: занятые покупатели отвечают поздно, поэтому ранние данные врут. На 3-й день агент склоняется к кампании A (как и рекламный кабинет), к 9-му меняет мнение с диффом, записывает урок и сам ужесточает своё правило принятия решений. Длинный горизонт становится видимым: память, которая пересматривает выводы, и агент, который учится на своей ошибке.

**Пять примитивов на экране.**
1. Ledger: одна append-only таблица Postgres, два времени (occurred / learned), идемпотентность через первичный ключ.
2. Commitments: агент сам назначает себе будущую работу и просыпается её выполнить.
3. Beliefs: версии с вероятностью (Beta-posterior), честный порог, дифф, уроки, версия политики.
4. Crash-safe runs: 7 шагов с чекпоинтами, эффекты с детерминированными ключами; «Pull the plug» реально убивает процесс, run продолжается с шага 4 без дублей.
5. Машина времени: ползунок по горизонту показывает весь продукт таким, каким его знал агент в день N.

**Архитектура.** Greenfield Next.js 16 на Vercel + Neon Postgres. Event sourcing: состояние = свёртка леджера. Чистый детерминированный движок: один код в тестах, демо и LIVE. Каждый посетитель получает изолированный воркспейс, сцена работает по отдельному ключу. Авторизации и оплаты нет: для победы они не нужны.

**Спонсоры: адаптеры с честным статусом (LIVE / READY / BLOCKED / ERROR).** Nimble: рыночные доказательства с источниками и повторное сканирование по обязательству. Liquid LFM: дешёвое мышление на каждом событии (экономика длинного горизонта), цитаты проверяются как точные подстроки, квалификацию решают правила. Tinybird: метрики «на дату» с дедупликацией. Публичное демо платные API не тратит.

**Процесс.** Контракт типов и бриф зафиксированы до старта; три агента в отдельных worktree (движок, интерфейс, презентация); один интегратор мёржит и деплоит.

**Сцена.** 8 битов одной кнопкой: запуск, «кабинет говорит A», поздние ответы, агент меняет мнение, поздняя правда из CRM, выдернутая вилка, сделка, машина времени.
